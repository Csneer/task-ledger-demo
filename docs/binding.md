# 宿主与 HTTP binding 草案

状态：设计候选，未实现、未冻结。本文件补足应用运行时需要的边界，不声称上游已经定义这些接口，也不构成可调用 API 文档。

## 采用方向

首个候选是 HTTP+JSON，独立客户端无须安装本项目 SDK。核心命令保持上游封套及 11 个 operation，不另发明 set-status；网络宿主提供可信 actor 和准入，核心负责角色、版本和对象语义。

可选的应用包装封套形如 `{command: <原样核心命令>, application: <可选应用参数>}`。application 用于创建时的项目关联和领取策略，不塞入核心未知字段，不携带客户端自报的 HostContext。具体字段、路径与错误映射在第一阶段契约中冻结，当前不生成 OpenAPI 或占位 handler。

| 接口能力 | 需固定的契约 | 负责层 |
|---|---|---|
| 登记/更新/停用参与者 | 操作者身份、稳定 ActorRef、资料 revision、凭据与显示资料分离 | registry + host |
| 创建与其他核心命令 | 原封套、应用伴随参数、授权、JSON 精确解析、事务及完整请求幂等 | transport + application + core |
| 定向资格修改 | issuer、仅 offered、策略 revision、与 claim 的竞争结果 | application + storage |
| 任务发现与查看 | 完整 TaskRef、过滤、分页边界、读取资格；列表候选不保证 claim 成功 | application + transport |
| 事实快照与时间线 | 快照水位、事件 cursor、去重、顺序、可见范围变化与过期错误 | storage + transport |
| 项目摘要与接续记录 | 源 TaskRef/revision/交付引用、摘要 revision、显式生成与更新 | application |
| 实施会话登记/更新/结束/接续 | ActivitySession 身份、关联承接、组合命令恢复、会话执行资格、presence 与任务状态分离 | activity + host |
| 可选唤起请求与结果核对 | 管理者登记的配置版本、Task 提交后可投递、目标身份、重复/未知结果、限流 | dispatch + launcher |

## 身份与准入

人和 Agent 的凭据都必须被宿主解析为 ActorRef。传输凭据机制由本项目选择，不能从客户端正文的 display_name、模型、actor 或管理员标记推断权限。首版凭据签发/轮换/吊销、开发环境认证方式和错误格式必须在开放真实 HTTP 服务前确定。

宿主分别计算新执行准入与历史回执读取资格。核心角色检查不会因为宿主准入通过而消失。代理某个人或 Agent 必须有真实代表关系；首版不提供管理员代替 issuer 验收的快捷路径。

## 请求与响应的承诺

- 保留 `protocol_version`、`command_id`、`expected_revision` 和完整 TaskRef。版本不支持时明确失败，不静默降级到 M1。
- 幂等记录需要包含核心命令和该次应用包装参数；键作用域与核心 actor/authority/command_id 对齐。历史读取准入通过后，完全相同的重试返回原提交；改变应用参数产生独立的 binding 冲突，不能以相同核心回执修改应用事实。
- 已成功请求的回执先于当前状态、定向策略和执行资格判断。响应必须标明重放，历史结果不能伪装成最新查询结果。
- 精确 JSON 解码要拒绝重复键、非法 Unicode 与越界数字，并保留数字等价规则；不能将全部 number 先转成 float64 再决定幂等相等。
- 核心错误保留其 kind；解析、认证、网络和应用错误各有明确作用域。超时或连接关闭表示结果未知，不能直接显示业务失败或安全重发新命令。
- Task、事实、事件、成功回执和伴随元数据必须原子提交。没有提交就不得回复成功，也不能在成功后遗漏事件。

以上是待实现承诺，不是当前代码能力。首次 binding 定案必须补齐精确错误类型、HTTP 映射和黑盒样例。

## 读取与接续

设计时明确：在同一一致性视图中取得快照和水位 W，再读取 W 之后的事件。cursor 是不透明的宿主游标；核心 event_id 不能作为全局时间戳。显示时间可以由宿主增加，但不能改写核心事件。应用登记/策略/接续事件应带自己的来源类型和 revision。

需要逐项定案：读取权限、过滤条件与水位关系、分页上限、空页含义、慢消费者行为、身份停用后的历史范围、断线后重连、未来保留策略。当前不设置回执或事件自动过期；如果容量有上限，明确拒绝而不丢弃未消费事实。

绑定定案后，用至少两个独立客户端通过公开接口完成一致事实读取，再进行[故障与负载验收](validation.md)。

## Skill 与 launcher 的应用接口

skill 的配置、注册回执、实施登记组合操作和可选唤起分别见[Agent 接入设计](agent-integration.md)。它们是本项目的应用接口，不冒充新核心 operation。外层登记请求需要稳定操作 ID 和每一步命令 ID，部分完成后恢复同一过程；不能把多个独立核心提交宣传成一笔不可见中间态的事务。

宿主必须把执行请求对应的可信 ActivitySession 绑定到 Assignment。仅声明相同 ActorRef 不足以接管另一个会话的 Run。新会话接续需明确交接或恢复核对；服务核对前不允许它开展该任务的外部工作。

launcher 仅处理已经提交并仍符合当前政策的 WakeRequest，使用管理者登记的命令配置。它报告启动事实，不代 Agent 领取任务；服务不向任意登记者开放提交 shell 文本并远程执行的接口。
