# 任务星轨前端

前端与 Go daemon 同源运行，构建 `cmd/taskledgerd` 会嵌入原生 ES modules、CSS 和 HTML；不需要额外前端开发服务器，也不依赖在线 CDN。使用 Node 20+ 执行前端测试，开发浏览器验证需要 `npm ci`。

## 使用

按[后台接入](backend.md)初始化并运行服务后，打开相同地址的 `/`，输入当前身份的 Bearer 凭据。凭据仅保存在当前浏览器标签页的 sessionStorage；连接身份由服务返回，不根据输入名称推断权限。断开连接会清除该页登录凭据；为同键恢复保留的请求、执行证明仍在该页存储中，关闭标签页会失去这些本地材料。

- 顶部工作区入口：切换项目、创建项目、登记参与者、切换身份。
- 任务链总览：桌面每页最多 12 组，手机每页最多 4 组；进入任务链后只显示该链，单任务过程只显示所选任务。
- 任务画布：拖动、缩放、适应；悬停看摘要，选择任务或搜索后定位，查看目标、交付与事件。
- 任务详情：按真实身份和状态提供子任务、多开尝试、领取、报告、交付、验收等操作。
- 底部事件条：显示最近事实，打开完整事件记录。断线保留已知状态，恢复后重新读取快照。

总览按同一 authority 内、完整 TaskRef 能匹配的显式 parent／related／depends_on 关系聚合；外部或未加载的引用不会把任务合并。聚合组仅是展示对象，不是可领取的协议 Task，也不赋予父子权限。页面根据 Assignment／Run／Submission 或已有承接代次区分“有实施记录”和“尚未承接”，不会按标题或测试前缀猜测任务用途。待验收与失败摘要优先帮助找到需要处理的工作。

链内筛选和以所选任务为中心的最多 24 节点邻域只改变显示范围；“X / Y”和局部轨迹提示说明当前显示量。筛选不会修改任务状态，也不表示隐藏任务没有历史。总览分页与局部图均为客户端展示，不是服务端分页。

每页 12／4 条是上限；较矮窗口根据实际画布高度减少数量，给标题、状态与底部控件保留空间。短屏采用紧凑播放条，镜头按当前节点和回放标签的实际高度定位，避免被播放器遮住。

画布中的“历史流转”按服务记录顺序播放，每一步同步点亮真实节点并显示操作者、动作和“领取前／第 N 轮承接”。节点另以“当前：”显示真实状态；历史不会覆盖当前事实或发出任务操作。默认镜头平滑跟随到可读位置；拖动或缩放会停止跟随但保留播放，可用“恢复跟随”接续。可暂停、重播、前后单步、调整速度，或点击操作标签定位。悬停可看最近 8 步；“本步详情”完整显示长参与者名称和轮次。

任务详情的回看入口进入真正的单任务显示范围，使用该 TaskRef 独立历史流；返回任务链或总览恢复对应范围。回放不抢键盘焦点。弹窗或本步详情展开时暂停自动推进和镜头，保留先前播放意愿；输入编辑、页面隐藏和离屏也会阻止自动镜头。系统启用“减少动态效果”时默认暂停，仍可用文字与单步查看。

历史按服务返回的提交顺序排列，不按位置、关系或时间戳推断因果。全局历史与单任务历史都有独立 cursor；分页批次读完后才呈现新增轨迹，不用新快照的 cursor 覆盖。全局最多保留 1200 个核心事件，独立单任务流最多 5000 个；截断会明确标为近期历史，不能把缓存尾部称为完整过程。任务时间线可另行分页读取历史。链内筛选与邻域裁剪产生的局部轨迹也会明确标记。

当前主要用于记录同一 Codex 会话及其子 Agent 的工作。主会话派生子 Agent 后，子 Agent 使用本项目 Skill 主动领取；网页不自动唤起进程。指定 Agent 只修改领取资格，不代表已领取或已开始。

## 重做与并行

失败／拒绝任务由 issuer 重新开放，使用同一 Task，下一次 claim 获得新 Assignment、generation 和 Run；历史交付和决定保留并配对展示。

已完成／已取消任务不重开，详情提供“新建重做”，产生 related 新任务。多开尝试每次创建 1–6 个独立 Task，用公开关系和 `io.taskledger.ui` 展示元数据分组。每项单独提交，出现错误会显示已确认数量；未知结果须先同键核对，明确未提交的剩余项可放弃。不会批量修改原任务状态或自动选择胜者。

## 凭据、会话与限制

浏览器领取时生成独立 session proof。只能使用自己保存且与当前执行绑定匹配的证明，不能借用 Agent 的 session ID 写报告。已有 Agent 的工作由该客户端报告／提交；issuer 可以从页面作决定或合法释放。

一个操作的多请求流程完成前，页面阻止切换身份或断开连接，关闭弹窗也不会解除这一保护。原写结果未知时，后续重试遇到凭据或权限拒绝仍保留原请求；恢复合法访问后继续核对，不能把这类拒绝当作原操作未发生。

主体登记不发行凭据；配置更新仍按后台的带外流程。当前目标策略仅支持指定 Agent，人可承接开放任务。无自动 launcher、任意命令执行、跨服务写入或自动汇总。

为避免浏览器浮点解析改变未知业务扩展，含其他命名空间扩展的任务暂不在页面修订预期；使用保留精确 JSON 的 Skill。页面使用完整 workspace snapshot，后端既有 1000 对象及 16 MiB 限制仍适用；超限明确显示错误。关闭标签页前核对所有未知操作；已有 Agent 客户端的持久意图日志不受影响。

## 验证入口

```sh
make check
npm ci
go build -o /tmp/taskledgerd ./cmd/taskledgerd
node scripts/frontend_fixture.mjs --daemon /tmp/taskledgerd --dir /absolute/new/private-directory
```

fixture 的首行 ready JSON 给出 URL、私有凭据文件路径、Codex Skill 配置和任务 ID，不输出凭据。它仅发布待领取任务，不伪造执行；实际 Codex 客户端或浏览器再去领取。

对这个隔离 fixture 运行真实浏览器验证：

```sh
CHROME_PATH=/usr/bin/google-chrome node scripts/frontend_e2e.mjs /absolute/new/private-directory
```

测试实际创建并流转隔离任务，覆盖多轮交付、子任务、多开、响应丢失同键重试与窄屏；不是只看截图。停止 fixture 会优雅停止其 daemon，保留数据库供检查。详细范围见[前端验收](validation/frontend-results.md)。
