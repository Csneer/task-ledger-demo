## 下一实施切片

下一步以 Developer Preview 的真实试用反馈和 S3 真人验收为主：本机 Codex、Pi、Claude Code 已通过[公开 binding](binding.md)完成任务委派、交付、issuer 验收和事件接续；远端 Codex 也已通过 SSH 转发完成独立领取、报告、交付及 issuer 验收，四客户端闭环通过。此前 SSH 超时及模型 502 保留为历史记录。后续前端已从本机经正常 CA/IP 校验的 LAN HTTPS 入口核对资产；本轮 Mac HTTPS 资产也已正常验证，但新版 Mac 浏览器真人操作、跨 authority 和完整压力容量仍未证明。

1. 已实现 HTTP、带外 Bearer 凭据映射、身份/项目/会话动作，以及公开快照和签名 cursor。
2. 已实现可安装 Skill 与持久请求意图助手；组合步骤仍各自提交，客户端保留原请求和每步 ID。
3. 本轮使用合成任务和自动化 `human` 主体验收，真实模型客户端执行计算与委派；不能据此声称真实人的日常 review 已通过。
4. 依据实际验收结果继续补齐 S3 日常恢复场景。handoff 和连续使用仍留在 S4；自动 launcher 不进入当前工作方式。
5. 已发布开发者预览并完成发行包、安装/运维流程、隔离冷态迁移和持久部署；接下来按 [真人验收](human-acceptance.md) 核对实际交付，记录试用反馈与后续版本需要解决的问题。

当前支持 11 个核心操作、10 个应用动作、7 个查询。`handoff.put`、`wake.request`、dispatch 动作及相关 S4 查询未实现；`profiles.list` 返回当前真实空目录。含 wake 的创建请求明确拒绝且整体回滚。

S1明确保留的限制是全工作空间读取、带外凭据/启动配置、1000任务有界快照、无自动历史清理、无issuer移交及外部进程停止保证。它们是已选择的初版边界，不以TODO代替实施契约；如果日常使用需要扩展，新增版本与证据。

## 上游反馈闭环

设计阶段即可登记[协议实践发现](protocol-findings.md)，标注规格推导与待实测项。每个实践问题先按[验证计划](validation.md)归类，附[证据模板](evidence-template.md)。协议缺口形成可审查的上游提案，Go 实现和宿主问题在本仓库处理；本轮不自动发布 issue。任何上游修订都要经过[协议升级记录](../protocol/UPGRADES.md)和重新验证，不让 demo 私有补丁成为隐含协议。

压测先产出测量结果，再给适合本机配置和使用规模的容量目标。零双重承接、零重复提交事实、零部分提交等语义不变量始终是硬条件，不能用吞吐指标掩盖。外部进程启动和外部业务副作用不自动获得 exactly-once 保证。吞吐/延迟数字不推广为协议所有实现的承诺。
