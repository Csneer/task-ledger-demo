# S3：后台与真实 Agent 客户端验收

日期：2026-10-31。结论：**本机后台与三种真实 CLI 的任务闭环通过；远端环境阻塞。完整 S3 真人日常验收仍未完成。**

本轮实现公开 Go 后台和轻量 Skill，并让实际 Agent CLI 通过 HTTP 操作隔离的合成任务。核心协议固定为 `task-core-draft-1`，上游 commit 为 `e6dae9a6127537af94f0f5127e8d590a1e6a3f1a`；本轮没有修改上游 Schema 或语义。

## 实现范围

| 能力 | 当前实现 |
|---|---|
| 后台 | `taskledgerd`，私有配置、一次性初始化、SQLite、HTTP/TLS 监听、优雅停止 |
| 写入 | 11 个核心操作、10 个应用动作；沿用 S2 原子事实/事件/回执 |
| 读取 | 7 个公开查询，完整快照、持久签名 watermark/cursor、固定批次与 follow 接续 |
| 身份 | 32 随机字节 Bearer 的摘要映射，独立 read/write/admin 能力；凭据更新重启生效 |
| Skill | 原始 JSON HTTP 助手、写前持久保存意图、私有会话证明、不自动重试 |
| 资源边界 | 1 MiB 请求、16 MiB 响应、1000 对象快照、200 事件页；加载 BLOB 前检查预算 |
| 明确未实现 | handoff、wake/dispatch 执行器、前端；不声明完整 binding 或跨 authority 互操作 |

## 参与客户端与链路

| 客户端 | 已核对版本 | 验收角色 |
|---|---|---|
| 本机 Codex | 0.164.0 | 领取父任务，发布定向子任务，验收子交付并汇总 |
| 本机 Pi | 0.85.1 | 使用 Skill 领取并交付；第三轮采用已有 `codex-proxy-local/gpt-5.6-luna` 配置 |
| 本机 Claude Code | 2.1.231 | 独立 HTTP 客户端领取和交付 |
| 远端 Codex | 0.164.0，仅只读探测 | 实际调用阶段 SSH 连接超时，环境阻塞，未证明交付 |

后台使用 loopback HTTP；远端原计划通过加密 SSH 反向转发访问，实际验收连接超时。没有形成远程互操作或直接 LAN HTTPS 证据。测试向客户端提供公开协议和独立工作目录，业务结果通过 HTTP 核对，不以数据库或内部 Go 包调用作为客户端证据。

父任务由自动化测试的 `human` Actor 发起。真实 Codex 发布的子任务由 Codex 自己验收，最后自动化 `human` Actor 验收父交付。**这里的人类主体是角色测试，不是真人在前端或 CLI 中阅读结果并作判断。**

## 联调过程中的环境与工具问题

本机 Codex 委派已运行。第一轮 Claude Code 的启动参数把提示词作为可变长度工具选项消费，客户端尚未执行；测试编排已改为从 stdin 传入提示词并重新运行。该问题属于验收工具调用，不是后台协议失败。

Pi 前两轮 CLI 返回 exit 0，但公开 `task.snapshot` 显示其任务仍为 offered，模型日志记录连接错误，没有实际领取或交付。验收脚本已补充模型错误及服务端事实核对，不能把进程退出码当业务成功。第三轮显式选择已有 `codex-proxy-local/gpt-5.6-luna` 配置后，Pi 完成领取、计算与交付，公开事实核对通过；前两轮的环境失败仍保留为联调记录。

远端最初只读版本探测成功，但实际调用阶段 SSH 连接在 5 秒截止后超时，随后独立 10 秒连接核对也超时。因此远端标为环境阻塞，后续本机验收不包含远端；不能把本机结果推广为跨主机通过。

Claude Code 第三轮在仅对该子进程移除代理环境后完成交付；没有修改全局配置。数据库、WAL 和 SHM 在实际 daemon 运行时的权限均已核对为 `0600`。

## 确定性真实 HTTP 反例

以下六项通过真实后台端口执行，独立于模型输出：

| 场景 | 已核对结果 |
|---|---|
| 同一创建命令 6 个并发请求 | 1 个首次成功、5 个回放，只产生一次成功事实 |
| 两个客户端竞争领取 | 1 个成功、1 个冲突 |
| 缺少会话证明后以原 ID 修正请求头 | 首次 403；补充证明后为首次成功，拒绝没有留下回执 |
| 旧 Assignment 迟到写入 | 409，任务快照保持不变 |
| 传输与解析拒绝 | 未认证 401、错误媒体类型 415、重复 JSON 键 400 |
| 固定范围事件 cursor 与篡改 | 读取到 7 个唯一事件；篡改 cursor 返回 400 |

这些结果证明对应一致性与拒绝路径，不是吞吐或压力容量基线。

## 自动化与审查证据

HTTP adapter 的 `httptest` 已覆盖真实 application 与文件数据库的登记、定向领取、执行、提交、issuer 验收、历史回放，以及认证/媒体类型/大小/错误映射。查询测试覆盖签名篡改、跨身份、scope、固定分页、重启、过滤、对象与字节容量。Skill 的临时 HTTP fixture 测试覆盖请求原文、意图并发发布、失败保留、私有权限和不泄漏证明。这些是各自层次的证据，不能代替上表真实 CLI 运行结果。

本轮 `make check` 已通过：114 个结构向量、全量 race 测试（application 90.230 秒、storage 1.282 秒）、7 个 Skill 回归测试（3.547 秒）、vet 和 build。后台独立审查通过，发现的两项中等问题已修复，无遗留阻断项。实现与报告一起提交；托管 CI 以[当前工作流](https://github.com/Csneer/task-ledger-demo/actions/workflows/ci.yml)中对应提交的结果为准，本地通过不预先代替托管结果。

## 已发现并修复的实现问题

1. 合法长 ActorRef/TaskRef 的组合键可能超过公开事件 Identifier 上限。超过 256 字符的组合键使用稳定 `sha256:` 标识；完整身份与 after-image 不变。
2. 并发打开 SQLite 时初始化偶发 BUSY。复现后仅对初始化增加 10 秒总时限内的 BUSY 重试，不重放应用事务。
3. 查询原先按行数限制，仍可能在容量判定前预载大量 BLOB。改为先查长度与累计预算，再加载内容；事件逐条读取并限制结果预算。
4. daemon 默认文件权限可能受宿主 umask 影响。当前启动时设私有 umask，并检查已有数据库及 sidecar 的私有权限。

这些是 demo 实现问题，不能据此宣称上游协议存在对应缺陷；长期历史成本仍需压测。

## 复现本机验收

从仓库根目录先构建后台，再调用已认证的本机三个 CLI：

```sh
go build -o /tmp/taskledgerd-acceptance ./cmd/taskledgerd
python3 scripts/agent_acceptance.py --binary /tmp/taskledgerd-acceptance --agent-timeout 420 --pi-provider codex-proxy-local --pi-model gpt-5.6-luna --claude-direct
```

上述 provider/model 是本机已有配置，本轮实际使用后通过，不是所有安装的通用默认值；其他环境应使用自己的有效配置。`--claude-direct` 只移除该测试子进程的代理环境，不修改全局设置。该命令会调用真实模型并使用既有账号资源，不属于普通 CI；运行目录、任务数据和 owned 进程由脚本记录与清理。远端使用另行明确授权的 `--remote` 参数，本轮不提供远端通过承诺。

本轮不证明全部 U/R 场景、真人日常 review、压力吞吐/延迟、磁盘断电、备份恢复、直接 HTTPS 部署、受控 launcher 或另一套 authority 的协议互操作。S3 后续出口以[路线图](../roadmap.md)和[验证计划](../validation.md)为准。
