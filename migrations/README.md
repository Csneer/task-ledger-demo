# SQLite schema v1

S2 的存储迁移由 [internal/storage/sqlite.go](../internal/storage/sqlite.go) 在打开文件数据库时执行，使用 `BEGIN IMMEDIATE`；`PRAGMA user_version=1` 与表创建同事务提交。

| 表 | 用途与约束 |
|---|---|
| `objects` | `(bucket,key)` 唯一，value 为不透明 BLOB；应用层存任务快照、成功回执、执行绑定及其他元数据 |
| `events` | 自增提交位置、全库唯一 event_id、不可变事件 BLOB；存储接口仅追加和读取，不提供删除 |

事务覆盖对象变更和事件追加。`Update` 在读取前取得 SQLite 写入资格，跨连接、Store 和进程串行执行读—判断—写；`View` 的全部读取使用同一个快照，调用方可一起读取对象与水位。存储层不自行解释协议或执行身份检查，应用必须在同一写事务中完成这些守卫。

采用 `modernc.org/sqlite v1.61.0`，每个连接使用 WAL、`synchronous=FULL`、`foreign_keys=ON`、5 秒 busy timeout。仅支持文件路径；拒绝内存库、空路径与客户端提供的 SQLite URI。父目录由调用方准备。

新库必须为空且 user_version=0；非空无版本数据库或未知版本明确拒绝，不猜测兼容性。没有自动降级、重建、删除历史或重算回执的迁移路径。未来升级必须先定义迁移与兼容规则，不直接改写此版本的含义。

验证命令：

```sh
go test -race ./internal/storage -count=1
```

测试覆盖文件重开、回滚、只读和生命周期、每连接配置、独立 Store 并发、跨进程竞争，以及子进程在提交前/提交后直接退出的恢复。后两者通过测试进程退出注入，生产代码没有故障环境变量或崩溃开关。

这些证据验证存储事务与进程崩溃恢复，不代表 HTTP、应用授权、磁盘断电、备份恢复、完整协议互操作或压力容量已经通过。正常文件系统和 SQLite 的持久化保证仍是运行前提。

S3 增加有界读取：先检查 BLOB 长度及累计预算，再加载内容，超预算明确拒绝，不返回部分快照。事件查询逐条读取，避免请求少量事件时提前加载整批大历史。响应编码后的 16 MiB 检查仍由应用层负责。

并发打开文件时，SQLite 初始化可能返回 BUSY。`Open` 仅对初始化阶段的 BUSY 在 10 秒总 context 内重试，其他错误立即返回；不会自动重放已开始的业务事务。daemon 创建数据库前设置私有 umask，并拒绝非私有数据库或 sidecar；直接使用 storage 包的调用方仍负责文件权限。
